# refigure — Claude Code memory

## Project
DOCX/XLSX→Markdown converters extracted from a private pipeline, DOCX+XLSX
only in one PyPI package — PDF excluded entirely (crowded market, not a
differentiator; see `docs/project-meta/converter-viability-assessment/
converter-viability-assessment-2026-08-04.md`). Differentiator: native
OOXML chart-data extraction (numCache/strCache, no rasterize/OCR/VLM) +
positioned zero-loss markers for composite figures — absent even in
well-funded incumbents (Docling issue #1287, >1yr open, unfixed).

## Git workflow
Routine changes (≤1-2 commits) — direct commit to `main`, no PR.
Substantial changes — `/tech-spec` → `/feature-workflow` → PR. No branch
protection on `main` yet (solo pre-release velocity, revisit at stage 8) —
also structurally unavailable regardless: repo is **private**,
`branches/main/protection` 403s ("Upgrade to GitHub Pro or make this
repository public"), resolves once the repo goes public for the PyPI
release. No required-status-checks rule means a merged PR's CI results
show no "required checks" banner — easy to misread as "CI didn't run,"
verify with `gh pr checks <n>` or the Checks API, not the merge box.

`delete_branch_on_merge: true` (a plain repo setting, available even on
private/Free) — merged PR branches auto-delete on GitHub, but local
tracking branches still need manual `git branch -d`/`-D`; `git fetch
--prune` only clears stale `remotes/origin/*` refs, not local branches.

## Package architecture
- One PyPI package, extras by format+capability: `[docx]`, `[xlsx]`,
  `[vlm]`, `[vlm-direct]`. Directory layout mirrors this: `refigure/core/`
  (`chart_data.py`/`chart_render.py`/`zipsafe.py`, always installed,
  lxml-only + optional `mermaidx`), `refigure/docx/__init__.py` (only
  submodule), `refigure/xlsx/` (`__init__.py` + `charts.py`),
  `refigure/vlm/` (`__init__.py` + `client.py` — `OpenRouterClient`/
  `OpenAIClient`/`AnthropicClient` — + `cache.py`). `api.py`/`_io.py`/
  `cli.py`/`__main__.py` stay at package root (`api.py` not in `core/` —
  its exception qualnames are asserted by string in tests, moving it
  breaks public surface for no gain). Public import paths are unaffected
  by any of this (`refigure.docx.convert` etc. resolve the same).
- **Extras-isolation bug class, found 3 times, only by the dedicated CI
  matrix leg** (never by the shared-venv suite, which has every extra
  installed): importing a package's submodule always runs its
  `__init__.py` first, so a module needing NO heavy dependency can still
  transitively require one — via (1) import ORDER (a guard positioned
  after another unguarded import in the same file — `xlsx_charts.py`,
  PR #8), (2) package NESTING (a cross-package-consumed module placed
  inside a guarded package — `docx_groups.py`, PR #11, fixed by keeping it
  a FLAT top-level module, not under `docx/`), or (3) a submodule of a
  guarded package needing an unrelated capability (`refigure/vlm/
  client.py`'s `OpenAIClient`, PR #12, needed no `pdfplumber` but inherited
  `vlm/__init__.py`'s guard anyway). Unlike (1)/(2), (3) was a REAL
  coupling (`Config.vlm_client`'s only call site always renders via
  pdfplumber first) — fixed by DECLARING it (self-referential extra,
  `vlm-direct = ["refigure[vlm]", ...]`), not restructuring. Full incident
  history: `project_extras_isolation_bug` memory.
- The guard itself must run BEFORE any same-package import, not just exist
  somewhere in the file (the PR #8 bug, above). `OpenAIClient`/
  `AnthropicClient` additionally use a CLASS-level (not module-level) guard
  variant — `client.py` hosts multiple independent capabilities, and
  `OpenRouterClient` must keep working with zero third-party deps
  installed.
- Optional-dependency pattern: module-level `try/except ImportError` +
  capability flag + `functools.lru_cache`-based warn-once via
  `logger.warning`. `refigure/cli.py` extends this — per-format dispatch
  imports `docx`/`xlsx` lazily so `refigure --help` works in a bare
  install.
- `refigure/xlsx/__init__.py` serializes `openpyxl.load_workbook()` behind
  a module-level `threading.Lock()` (`_OPENPYXL_LOAD_LOCK`) — openpyxl
  shares ONE `lxml.etree.XMLParser()` across every thread internally, a
  real concurrency bug found via PR #9's CI
  (`project_openpyxl_concurrent_parser_fragility`). `docx/__init__.py` has
  no such constraint — refigure's own lxml usage never shares a parser
  instance across threads.

## Public API
Rich, not a bare string — full rationale in `docs/project-meta/
v1-scope-and-api-design/v1-scope-and-api-design-2026-08-04.md` §3:
- `ConversionResult` dataclass: markdown + warnings + charts_found/rendered
  + groups_found + vlm_used.
- Typed exceptions: `UnsupportedFormatError`, `CorruptArchiveError`,
  `MissingOptionalDependencyError`.
- `strict: bool` — raise vs. degrade-with-warning on a missing capability.
- Input: path or bytes/file-like, not path-only.
- Config/client object, not a kwarg pile.
- Sync by default (the source pipeline's own VLM HTTP client confirmed
  fully sync, not assumed). Async is NOT for the whole library — only a
  later, narrow VLM-batch entry point, decided when VLM ships.
