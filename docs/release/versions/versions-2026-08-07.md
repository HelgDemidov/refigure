### Команды релиза

#### Уже выполнено, в этом порядке

```bash
# 1. Убедиться, что стоим на main и он чист
cd "/home/fastcentrifuge/Рабочий стол/Projects/Dev/refigure"
git checkout main
git status --porcelain   # должно быть пусто

# 2. Бампнуть версию + закоммитить + создать ЛОКАЛЬНЫЙ тег
#    (main-only guard, semver-валидация, отказ на грязном дереве —
#    см. scripts/release.sh)
./scripts/release.sh 0.1.0
#   -> pyproject.toml: 0.0.0 -> 0.1.0
#   -> коммит c348ba9 "chore: release 0.1.0"
#   -> локальный аннотированный тег v0.1.0
#   -> печатает инструкцию для следующего шага, сам её не выполняет

# 3. Запушить коммит с версией (НЕ тег — паблиш не триггерится)
git push origin main
```

Плюс одноразовая инфраструктурная подготовка (не повторяется для
будущих версий, уже сделана раз и навсегда):

```bash
# GitHub-сторона: окружение pypi + deployment-tag-policy "v*"
SETUP_GITHUB_ENVIRONMENT_YES=1 ./scripts/setup_github_environment.sh
```

и вручную на pypi.org: **Manage `refigure` → Publishing → GitHub Actions**
→ owner `HelgDemidov`, repo `refigure`, workflow `publish.yml`,
environment `pypi`.

#### Остался один шаг — единственная точка необратимости

```bash
git push origin v0.1.0
```

Это и только это запускает `.github/workflows/publish.yml`: сборка →
`pypa/gh-action-pypi-publish` (OIDC, без токена) → реальная публикация на
PyPI. PyPI не позволяет переиспользовать номер версии даже после `yank` —
делать осознанно, не как побочный эффект чего-то другого.

После выполнения: обновить строку «Публикация выполнена?» выше на `Да`
+ дату, и статус раздела на `опубликовано`.
