## 3. Демо-визуал (дизайн-план, по итогам `frontend-design`, ревизия по
   замечанию пользователя 2026-08-06)

Формат: **один SVG-файл** (не PNG/GIF) — нулевые новые зависимости, чёткий
на любом зуме GitHub, тривиально форкается в light/dark копии сменой
заливок. Пересмотр исходного плана: OUTPUT — не «сырой текст ВМЕСТО
превью», а **один и тот же файл, показанный двумя читателями**. Рендер —
не новая генерация «для картинки»: `refigure.core.chart_render.
mermaid_renders()` уже вызывает `mermaidx.render(code).svg()` на каждый
чарт-кандидат перед тем, как включить его в вывод (verify-часть
verify+fallback, `chart_render.py`) — переиспользуем этот же вызов, не
изобретаем отдельный рендер-пайплайн для демо.

- **Композиция**: `INPUT` (скриншот реального чарта) → стрелка
  `refigure.docx.convert()` → `OUTPUT`, один блок с ДВУМЯ подписанными
  видами одного файла: (1) сырой ```` ```markdown ```` -текст, подпись «as
  your LLM/RAG pipeline reads it»; (2) тот же ```` ```mermaid ```` -fence,
  отрендеренный (тот самый SVG из `mermaidx.render()`), подпись «same file,
  rendered — as GitHub renders it automatically». Не 3 независимых панели —
  один output, два чтения, чтобы не размывать единственный сигнатурный
  акцент (стрелка = реальный API-вызов, не декоративный градиент).
- **Точность заявления**: caption **не** говорит «визуальный клон вашего
  чарта» — mermaid-рендер использует собственную типографику/цвета, не
  тему исходного Excel/Word-чарта. Заявление — «те же числа/подписи,
  доступны для повторной визуализации», не «пиксель-в-пиксель копия».
  Прямое следствие уже принятого в проекте анти-хайп правила (`CLAUDE.md`
  §Do NOT).
- **Бесплатный бонус для §4**: `examples/*.md` не нуждаются в отдельном
  рендер-шаге — GitHub нативно рендерит ```` ```mermaid ```` -fence при
  просмотре `.md`-файла в репозитории. «Картинка на выходе» для полных
  примеров уже закрыта самим GitHub бесплатно — ручная композиция нужна
  только hero-визуалу (он живёт как `<img>`/`<picture>` в самом README, вне
  markdown-рендера отдельного файла).
- **Выбор исходного чарта — верифицирован живым вызовом `convert()`
  2026-08-06, не по заметкам `manifest.yaml`** (заметки фиксируют OOXML
  `chart_type`, не то, прошёл ли конкретный чарт verify+fallback до
  mermaid — разное: у `hackair-d7.7-pilot-evaluation.docx` 6 из 8 чартов
  технически рендерятся как mermaid, но с общей меткой оси `"Category 1"`
  — реальный предел словаря `xychart-beta` при single-category-multi-series
  чарте, не баг и не повод чинить сейчас, но плохой hero-визуал).
  Рекомендованный hero-чарт: `foodrus-dashboard.xlsx`, первый чарт
  (`xychart-beta`, подписанные категории `RFID/WSN/WiFi/GPRS/Bluetooth/…`,
  реальные значения 246→25) — читаемый, подписанный, проверен вживую.
  **Общее правило для реализации**: любой чарт/документ, попадающий в §3
  или §4, подтверждается реальным вызовом `convert()` перед фиксацией в
  README, не берётся из `manifest.yaml`-заметок на веру.
- **Палитра** (5 именованных hex, «спецификация», не маркетинг): бумага
  `#FAFAF8` / чернила `#1A1A1A` / акцент recovered-данных teal `#1E7A6E`
  (панель `OUTPUT`, обе подпанели) / акцент native-chart blue `#3B5BA5`
  (панель `INPUT`) / структурный серый `#8A8A82` (стрелка, подписи,
  разделители). Никакого «конкурент плохой»-акцента — единственная
  сравнительная подпись («native OOXML `numCache` — not OCR») текстовая,
  не отдельный визуальный элемент.
- **Типографика**: моно (JetBrains Mono/IBM Plex Mono) — сырой текст и
  данные; гуманистический sans (Inter/IBM Plex Sans) — только
  капшены-подписи ролей («as your LLM reads it» и т.п.).
- **Theme-aware**: `<picture><source media="(prefers-color-scheme: dark)"
  srcset="docs/assets/demo-dark.svg"><img src="docs/assets/demo-light.svg">
  </picture>` в README — GitHub рендерит `<picture>` в markdown корректно;
  ни у одного из трёх конкурентов нет тёмной версии баннера.
- Файлы: `docs/assets/demo-light.svg` + `demo-dark.svg`. Генерация —
  локальный скрипт при реализации (`/feature-workflow`): скриншот
  исходного чарта (LibreOffice/Office) + `mermaidx.render()` на реальный
  mermaid-fence из `convert()` + композиция в SVG — не часть
  `refigure/`-пакета, не рантайм-зависимость.

## 4. Реальные примеры (таблица, marker-style)

Новая директория `examples/` (корень репо, не `docs/` — англоязычный,
пользовательский материал, не проектная документация). 3 файла, оба
дифференциатора + оба формата:

| Источник | Что демонстрирует | Файл |
|---|---|---|
| `hackair-d7.7-pilot-evaluation.docx` | нативное извлечение chart-данных (8 чартов, 6 — валидный mermaid) | `examples/hackair-native-charts.md` |
| `onehealth-ejp-d3.20.docx` | комбо: 5 нативных чартов (все 5 — валидный mermaid, подписанные категории) + 1 composite-группа (zero-loss маркер) в одном документе | `examples/onehealth-combo.md` |
| `govtech-2025-charts.xlsx` | XLSX в масштабе (55 чартов, 33 — валидный mermaid) | `examples/govtech-xlsx-charts.md` |

Каждый файл — короткая шапка (источник/лицензия/attribution, тот же
формат, что `ATTRIBUTION.md`) + полный `convert()`-выход целиком. Все три
источника и все счётчики (charts/mermaid/groups) верифицированы живым
`convert()`-вызовом 2026-08-06, не взяты из `manifest.yaml` на веру (см.
§3). Открывая любой файл на github.com, читатель одновременно видит
исходный ```` ```mermaid ```` -текст и его нативный GitHub-рендер — «картинка
на выходе» без отдельного шага генерации (§3, «бесплатный бонус»).

`onehealth-ejp-d3.20.docx` заменяет исходно рассматривавшийся
`swd2018-254-marine-litter-ia-annex.docx` — у последнего единственный чарт
подтверждённо падает в table-only (0 mermaid-блоков, verify+fallback
сработал на реальных данных), для комбо-примера с mermaid не подходит,
хотя сам факт table-only fallback — тоже честный, просто не для ЭТОЙ
демонстрации.

## 5. Проверяемое заявление о зрелости

Точные цифры, суммированные из уже запиненных regression-baseline'ов
(`_PINNED_DOCX_VALUES`/`_PINNED_XLSX_VALUES`, `tests/integration/
test_{docx,xlsx}_corpus.py`) — не новые вычисления, не оценка:

**27 документов (15 docx + 12 xlsx), 407 нативных чартов (400
отрендерено), 35 composite-групп.**

Формулировка в README — ровно по образцу `CLAUDE.md` §Do NOT: «протестировано
на 27 реальных документах…», ссылка на `tests/integration/fixtures/
manifest.yaml`. Без «battle-tested»/«production-ready».
