## 0. Что и зачем

`README.md` сейчас — плейсхолдер (61 строка, есть тэглайн/статус/CLI/лицензия,
нет демо). Стадия 7 (`execution-sequence-2026-08-04.md`, 9%) требует

дизайн-документу (`v1-scope-and-api-design` §4, п.6) содержательная работа,

блокирует 4b/5/6, усиливает предпосылку 6b (CLI уже есть, README должен его
показать). Скоуп: `README.md` целиком + новый демо-ассет + новая директория
`examples/` с реальными выходами конвертера. Не трогает `refigure/` —
инварианты (format-isolation/core-lightness/sync/rich-API) структурно

## 3. Демо-визуал — ДВА hero-ассета (реализовано 2026-08-06, финальная
   версия; заменяет исходный план на один ассет)

**Пересмотр в ходе реализации**: план ниже изначально описывал один
SVG (нативное извлечение чартов). Пользовательский вопрос при сдаче —
«у нас один такой пример или несколько? что насчёт docx?» — вскрыл, что
единственный hero показывал бы не самый уникальный дифференциатор:
нативное извлечение чартов ценно, но не уникально; **zero-loss маркеры
для composite-групп — уникальны** (absent even at Docling, issue #1287),
и это DOCX-only способность, xlsx-hero её вообще не касается. Решение:
**два hero-ассета**, не один — общий дизайн-язык (dual-view `OUTPUT`,
единственная стрелка-сигнатура, ranked-fade колонка), но каждый под свой
дифференциатор, роли акцентных цветов зеркально меняются местами (chart
hero: blue=`INPUT`/teal=`OUTPUT`; groups hero: teal=`INPUT`/blue=`OUTPUT`)
— пара читается как набор, не как дубликат.

Формат обоих — **SVG** (не PNG/GIF) — нулевые новые зависимости, чёткий
на любом зуме GitHub, light/dark — раздельные файлы (не CSS-переключение
заливок: см. theme-aware ниже).

### 3a. `demo-light.svg`/`demo-dark.svg` — нативное извлечение чартов (xlsx)

`INPUT` (реальный скриншот чарта) → стрелка `refigure.xlsx.convert()` →
`OUTPUT`, один блок с ДВУМЯ подписанными видами одного файла: (1) сырой
markdown-текст, подпись «as your LLM/RAG pipeline reads it»; (2) тот же
mermaid-fence, отрендеренный. **Не «as GitHub renders it automatically»**
— рендер использует кастомную mermaid-тему (см. ниже), значит не буквально
то, что покажет голый fence на GitHub; итоговая подпись — «same file,
rendered» (точность важнее эффектности, тот же анти-хайп принцип
`CLAUDE.md` §Do NOT).

Источник — верифицирован живым `convert()`, не по заметкам
`manifest.yaml` (те фиксируют OOXML `chart_type`, не то, прошёл ли чарт
verify+fallback до mermaid — у `hackair-d7.7-pilot-evaluation.docx` 6 из 8
чартов технически mermaid, но с общей меткой оси `"Category 1"`, реальный
предел словаря `xychart-beta` при single-category-multi-series). Финальный
выбор: `foodrus-dashboard.xlsx`, первый чарт (`RFID/WSN/WiFi/…`, значения
246→25) — из реального скриншота выяснилось, что круглая «бейдж»-диаграмма
сама обрезает 3 из 10 подписей по своей же окружности (баг источника, не
наш кроп — подтверждено сравнением с полным разворотом страницы); демо это
честно подписывает и показывает, что `convert()` восстанавливает все 10.

**Ranked color-fade** — не решено с нуля: адаптирован живой паттерн из
`scopus_search_code`'s `chartColors.ts` (`getRankedBarColor`/`mixHex`,
найдено чтением реального кода, не по памяти) — линейная RGB-интерполяция
от насыщенного базового цвета к ink/paper-токену темы, `t = (i/(n-1))×0.88`.
Применить пришлось **постфактум к сырым `<rect>` в SVG**, не через
mermaid-конфиг: `themeVariables.xyChart.plotColorPalette` циклит цвета
ПО ДАТАСЕТАМ, не по барам внутри одной серии (подтверждено эмпирически,
у mermaid `xychart-beta` нет хука для per-bar темизации). Заодно найдены и
исправлены mermaid-дефолты: `plotColorPalette` без темы почти не виден на
белом (низкий контраст), `themeVariables.fontSize` дефолт 16px даёт
нечитаемый эффективный размер при масштабировании SVG (~0.49×) —
поднят до 27px, проверено, что не возвращает коллизию подписей на 10
категориях.

**Пропорции**: раскладка 46:54 (текстовая панель:рендер-панель, было
~58:42) — рендер-панели графика отдана большая доля, чтобы шрифт mermaid
читался; `INPUT`-панель расширена на 70px за счёт незанятого запаса в
`OUTPUT`-колонке (та была height-bound, не width-bound — резерв нашёлся,
не был впритык). Контраст серого `muted` пересчитан по WCAG:
`#8A8A82`/`#FAFAF8` — 3.33:1 (не проходит AA), заменён на `#63635A` —
5.8:1; тёмная тема (`#9A988F`/`#14150F`) уже была 6.35:1, не тронута.
Стрелка — литеральный `>>>>>` (моно, отрицательный letter-spacing), не
`<line>`+`<path>`.

### 3b. `demo-groups-light.svg`/`demo-groups-dark.svg` — zero-loss маркеры
   для composite-групп (docx)

**Черновая версия (первая попытка) была забракована пользователем и
переделана** — источник учебной ценности, оставлено как явка, не
затёрто: изначально взят `efsa-trichinella-dashboard-guide.docx` (9
групп, «Figure 1» = скриншот вкладок дашборда). Проблема — не баг
конвертера (проверено разбором сырого XML: группа = 2 встроенных
изображения в `wpg:wgp`, 0 `w:tbl` — детектор структурно не может
сработать на таблицу, ищет конкретно `wpg:wgp`), а неудачное ДЕМО: (1)
скриншот вкладок не читался как «фигура» с первого взгляда; (2)
`OUTPUT`-панель показывала 9 одноцветных квадратов без текста — у этой
конкретной группы `captions` пуст («Figure 1:» идёт отдельным параграфом
ПОСЛЕ группы, не внутри неё), абстрактная заливка выглядела как
бессмысленная заглушка, не как «восстановленные данные».

**Финальный источник**: `onehealth-ejp-d3.20.docx` (671 страниц у
LibreOffice, страница 380 — найдена live через `pdftotext`, не
предположена), единственная composite-группа в файле — круговое
филогенетическое дерево *C. parvum* с 4-элементной цветовой легендой,
**с непустыми captions** («Europe/USA cluster 1; Europe cluster 2;
Europe cluster 3; Asia/Africa cluster 4» — реальный текст из
`convert()`). `OUTPUT`-панель показывает эти 4 строки как подписанные
чипы (не абстрактные квадраты) — честная, содержательная демонстрация:
«рисунок дерева теряется, но его легенда — нет».

Композиция зеркальна 3a: `INPUT` (реальный скриншот дерева+легенды) →
`refigure.docx.convert()` → `OUTPUT` dual-view (сырой текст маркера +
4 ranked-fade чипа, синий якорь вместо зелёного — по прямому указанию
пользователя, чтобы пара читалась как набор). Кроп сделан с запасом
(верифицирован по полному развороту страницы) — без обрезки круга снизу
и без наложения `INPUT`-подписи на содержимое, тот же класс ошибки, что
и в 3a на первой итерации.

### Общее для обоих ассетов

- **Палитра** (5 именованных hex на тему): бумага `#FAFAF8`/ink `#1A1A1A`
  (light), `#14150F`/`#EDEDE6` (dark); teal `#1E7A6E`/`#4FBBA8`, blue
  `#3B5BA5`/`#7C9CD6`, серый `#63635A`/`#9A988F` (обе ≥4.5:1 к фону).
  `INPUT`-подпись — ФИКСИРОВАННЫЙ (не потемный) цвет в обоих файлах: она
  всегда лежит на белом фоне реального скриншота, а не на фоне страницы —
  тёмная тема даёт `#7C9CD6`/`#4FBBA8` низкий контраст именно там (2.8:1
  на белом), поэтому используется светлый вариант в обеих SVG.
  Без background-«чипа» под подписью — только сама надпись (пользователь:
  фон скриншота не должен подменяться, только добавляться текст поверх
  чистого белого поля исходника, где оно есть).
- **Типографика**: моно (JetBrains Mono) — сырой текст/данные;
  гуманистический sans (Inter) — капшены-подписи.
- **Theme-aware**: `<picture><source media="(prefers-color-scheme: dark)"
  srcset="…-dark.svg"><img src="…-light.svg"></picture>` в README.
- Файлы: `docs/assets/demo-{light,dark}.svg`,
  `docs/assets/demo-groups-{light,dark}.svg`. Генерация —
  `scripts/gen_demo_asset.py`/`scripts/gen_demo_asset_groups.py`
  (не часть `refigure/`-пакета, не рантайм-зависимость, не в CI) —
  оба скрипта **самопроверяющиеся**: рендерят реальный `convert()` перед
  композицией и падают `assert`-ом, если факт (число категорий/групп,
  текст captions) разошёлся с тем, что зашито в подписи ассета.

## 4. Реальные примеры (таблица, marker-style)

Новая директория `examples/` (корень репо, не `docs/` — англоязычный,
пользовательский материал, не проектная документация). 3 файла, оба
дифференциатора + оба формата:

| Источник | Что демонстрирует | Файл |
|---|---|---|
| `hackair-d7.7-pilot-evaluation.docx` | нативное извлечение chart-данных (8 чартов, 6 — валидный mermaid); 280KB markdown | `examples/hackair-native-charts.md` |
| `swd2018-254-marine-litter-ia-annex.docx` | комбо: 1 чарт (table-only — реальный verify+fallback в деле, не каждый чарт мапится на mermaid) + 2 composite-группы (zero-loss маркеры) в одном документе; 288KB markdown | `examples/swd2018-combo.md` |
| `govtech-2025-charts.xlsx` | XLSX в масштабе (55 чартов, 33 — валидный mermaid); 78KB markdown | `examples/govtech-xlsx-charts.md` |

Каждый файл — короткая шапка (источник/лицензия/attribution, тот же
формат, что `ATTRIBUTION.md`) + полный `convert()`-выход целиком. Все три
источника и все счётчики (charts/mermaid/groups) верифицированы живым
`convert()`-вызовом 2026-08-06, не взяты из `manifest.yaml` на веру (см.
§3). Открывая hackair/govtech на github.com, читатель одновременно видит
исходный ```` ```mermaid ```` -текст и его нативный GitHub-рендер — «картинка
на выходе» без отдельного шага генерации (§3, «бесплатный бонус»); у
swd2018 эта строка демонстрирует другую половину контракта — честный
table-only fallback, не mermaid, см. ниже.

**Ревизия при реализации (2026-08-06):** изначально комбо-строка целилась в
`onehealth-ejp-d3.20.docx` (5/5 чартов — валидный mermaid + 1 группа) —
технически лучше по mermaid-покрытию, но живой прогон показал 1.34MB
markdown (исходник — 30MB отчёт). GitHub не рендерит Markdown-файлы такого
размера в блоб-вьюере репозитория (порог заметно ниже 1MB, точное число не
задокументировано публично, но подтверждено многократными issue на
github/markup) — сломало бы именно «бесплатный бонус» из §3 для этого
файла. Возврат к `swd2018-254-marine-litter-ia-annex.docx` (288KB) — тот же
класс проверки («любой документ подтверждается живым вызовом»), просто
проверка поймала и файл-размер, не только mermaid-пригодность.

## 5. Проверяемое заявление о зрелости

Точные цифры, суммированные из уже запиненных regression-baseline'ов
(`_PINNED_DOCX_VALUES`/`_PINNED_XLSX_VALUES`, `tests/integration/
test_{docx,xlsx}_corpus.py`) — не новые вычисления, не оценка:

**27 документов (15 docx + 12 xlsx), 407 нативных чартов (400
отрендерено), 35 composite-групп.**

Формулировка в README — ровно по образцу `CLAUDE.md` §Do NOT: «протестировано
на 27 реальных документах…», ссылка на `tests/integration/fixtures/
manifest.yaml`. Без «battle-tested»/«production-ready».
